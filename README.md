# Design Service System

## Описание проекта
Система для просмотра услуг по дизайну и управления своими заказами.  
Пользователь может просматривать список услуг, добавлять их в корзину, отменять заказы, а также скачивать данные о сервисах и заказах в форматах JSON, HTML или XML.

---

## Реализация бэкенд-сервисов

### 1. GET-сервис, возвращающий HTML-страницу с фронтендом
- **Маршрут:** `/`  
- **Описание:** Отдает HTML-страницу с интерфейсом для просмотра услуг и корзины.  
- **Функции фронтенда:** отображение списка услуг, блока корзины и кнопок для скачивания.

### 2. GET-сервис, возвращающий JSON
- **Маршрут:** `/api/services`  
- **Описание:** Возвращает JSON со списком доступных услуг.  
- **Пример JSON:**
```json
[
  { "id": 1, "title": "Logo Design", "place": "Remote", "price": 150 },
  { "id": 2, "title": "UI/UX Design", "place": "Remote", "price": 300 }
]
```
### 3. POST-сервис для получения корзины пользователя
- **Маршрут:** `/api/cart`  
- **Описание:** Принимает `userId` в теле запроса и возвращает JSON с текущими заказами пользователя.

### 4. POST-сервис для добавления заказа
- **Маршрут:** `/api/book`  
- **Описание:** Принимает `userId` и `serviceId`, добавляет услугу в корзину и возвращает сообщение о результате.  
- **Обработка ошибок:** если услуга уже в корзине, возвращается ошибка.

### 5. DELETE-сервис для отмены заказа
- **Маршрут:** `/api/book/:id`  
- **Описание:** Удаляет заказ по `id`.  
- **Обработка ошибок:** если заказ не найден, возвращается 404.

### 6. GET-сервис для скачивания данных в разных форматах
- **Маршрут:** `/api/export`  
- **Описание:** Возвращает данные о сервисах в формате JSON, HTML или XML в зависимости от заголовка `Accept`.  
- **Примеры заголовков Accept:**
  - `application/json` → JSON  
  - `text/html` → HTML  
  - `application/xml` → XML

### 7. Работа с JSON-файлами
- Данные о сервисах и корзине хранятся в `services.json` и `cart.json`.  
- Система продолжает работу при изменении этих файлов.

### 8. Обработка исключительных ситуаций
- Добавление дубликата в корзину.  
- Попытка удаления несуществующего заказа.

## Реализация фронтенда

### 1. Получение данных с бэкенда
- `GET /api/services` → формирует блок услуг.  
- `POST /api/cart` → загружает текущие заказы пользователя.

### 2. Отображение данных
- Список услуг с кнопкой **Order**.  
- Корзина с заказами и кнопкой **Cancel** для каждого заказа.  
- Заголовок **My Orders** и кнопки для скачивания файлов.

### 3. Изменение данных по событиям
- При нажатии **Order** отправляется `POST /api/book` и обновляется корзина.  
- При нажатии **Cancel** отправляется `DELETE /api/book/:id` и корзина обновляется.

### 4. Скачивание данных
- Кнопки **Download JSON**, **Download HTML**, **Download XML** отправляют `GET /api/export` и скачивают данные в соответствующем формате.

### 5. Взаимодействие с пользователем
- Кнопки имеют эффекты hover/active.  
- Услуги и корзина выровнены по центру страницы.
